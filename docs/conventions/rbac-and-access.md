# RBAC + access control

The 5-phase access-control rebuild, the multi-user gap closures, and the additive grant shapes. Read before touching auth, scoping, or any `UserCanAccess*` path.

> Extracted verbatim from `CLAUDE.md` on 2026-11-11 (U-788) to take it off the

> before. Read this file when touching the area; CLAUDE.md keeps the one-line rule and
> links here.

---

- **RBAC chain**: User → UserRole → Role → RoleModule → Module. Role entity is the core — UserRole and RoleModule are join tables. Role assignment is managed inline on the User Profile page. Authorization middleware: `shared/rbac.require_module_api(Modules.X, "can_read"|"can_create"|…)` FastAPI dependency on every entity router; permission map is cached per `(user_sub, company_id)` for 5 minutes.
- **Access Control Rebuild — all 5 phases shipped 2026-04-30 → 2026-05-06.** The rebuild replaced single-tenant role-name "admin" gating with a multi-tenant model. JWT carries `uid` (User.PublicId), `cid` (active Company.PublicId), `isa` (IsSystemAdmin) claims. Auth dependency populates `current_user_id` / `current_company_id` / `current_is_system_admin` ContextVars per request. `User.IsSystemAdmin = 1` is the bypass primitive (replaces role-name "admin"); Christopher (id=17) + Claude Agent (id=33) have it. Apple Reviewer (id=32) was downgraded 1→0 on 2026-05-12 post-approval. Permissions are the OR-union across every UserRole row for the (user, active Company) pair, with UserModule additive read-only on top. Cache key is `(user_sub, company_id)` — switching Companies via `POST /api/v1/auth/switch-company` invalidates and re-resolves. `JWT_CID_GRACE_DAYS=0` (default since Phase 2) — tokens missing `uid`/`cid` claims fail closed, no DB fallback. Phase 3 enforces TimeEntry row scoping by UserId. Phase 4 added `Workflow.CreatedByUserId` FK + `IsAgent` filter on user lists (default-hidden, opt in via `?include_agents=true`). Phase 5-thin added `CompanyId NOT NULL` + `DEFAULT (1)` to 24 tenant-data tables (zero code change — DEFAULT fires on any INSERT that omits the column). Phase 5b (multi-tenant filtering enforcement) deferred until a 2nd Company arrives. See `project_access_control_rebuild.md` for the full breakdown.
- **Multi-user RBAC gaps closed 2026-05-06** (separate from the 5-phase rebuild). **Gap 3** (`commit 64a2a05`): self-service `POST /api/v1/auth/change-password` + `POST /api/v1/mobile/auth/change-password`; user stays logged in via fresh tokens. Admin password reset via `set_credentials_for_user` now revokes target user's outstanding refresh tokens. New `RevokeAllAuthRefreshTokensByAuthId` sproc + `revoke_all_for_auth_id` repo method. **Gap 2** (`commit 361d248`): `CreatedByUserId BIGINT NN FK User.Id` on 30 transactional + reference entities (the 24 from Phase 5 + Vendor / Customer / SubCostCode / CostCode / PaymentTerm / ProjectAddress). Same DEFAULT-trick pattern as Phase 5 (DEFAULT 17 = Christopher). `ModifiedByUserId` deliberately skipped — Workflow audit trail covers it. **Service-layer threading shipped 2026-05-07 in 4 phases** (commits `a80cff3`, `8bb79c4`, `f059ddc`, `465e9bd`) — every Create + Upsert sproc across the 30 entities now accepts `@CreatedByUserId BIGINT = NULL` with `COALESCE(@CreatedByUserId, 17)` fallback for scheduler / system context; services thread `current_user_id` ContextVar through. Migrations: `scripts/migrations/gap2_{core,adjacent,reference}_threading.sql`. Empty-bill edge case from Gap 1 closed alongside Phase Core via `dbo.UserCanAccess{Bill, BillCredit, Expense, Project}` UDFs gaining a "creator can access their own row" clause. Skipped: `ReviewEntry` (decommissioned, no Create sproc — falls away when table drops). **Gap 1** (`commit e2d3afb`): per-user transactional data isolation via `UserProject` membership. Non-admin users see only Bills / BillCredits / Expenses / Invoices / ContractLabor / Projects on projects they have UserProject access to; system admins (`IsSystemAdmin=1`) bypass. List-path scoped (Read*, ReadPaginated, Count*); by-id direct-lookup tightening shipped 2026-05-07 via service-layer post-fetch checks in `shared/access.py` using the existing `dbo.UserCanAccess*` UDFs — `BillService.read_by_*`, `BillCreditService.read_by_*`, `ExpenseService.read_by_*`, `InvoiceService.read_by_*`, `ContractLaborService.read_by_*` plus the four line-item child services all gate on UserProject membership. Mutations (update/delete/complete) inherit because they fetch via `read_by_public_id` first. `EntityNotAccessibleError` maps to HTTP 404 (not 403) so the URL doesn't confirm the entity exists. Bill/BillCredit use IN-subquery against parent line-item × UserProject join (the only shape the optimizer materializes once at parameter-substitution time, vs the 113-second per-row EXISTS that v1/v2 attempted). **Expense's `ReadExpensesPaginated` has since moved to the scalar `UserCanAccessExpense` UDF per row** (after the LIKE search, which CONVERTs ExpenseDate/TotalAmount per row — non-sargable); fine at ~12K rows, worth a watch. Plus `b.[CreatedByUserId] = @ActorUserId` clause keeps empty drafts visible to their creator. Cutover: 12 agent users × 131 Projects = 1572 UserProject rows backfilled so the agent fleet doesn't go blind; humans keep their explicit assignments.
- **UserModule additive grant**: `UserModule` rows are merged on top of `RoleModule` as **read-only** (`can_read=true`, others false). Implemented in `shared/rbac.py::_resolve_permissions_from_db` (uses `types.SimpleNamespace` to mimic `RoleModule`'s attribute shape, scoped by `read_all_by_user_id_and_company_id`) and mirrored in `entities/auth/api/router.py::_resolve_me_payload`. Never downgrades a role-granted module. `entities/user_module/api/router.py` calls `invalidate_all_caches()` + `publish_profile_changed(user_id)` on every mutation so grants take effect within ~1s, not after the 5-min TTL.
- **UserProject informational only (2026-04-29)**: `/auth/me` exposes `accessible_project_ids: number[]` derived from `UserProject` rows. **No** per-endpoint filtering by project anywhere. Field is published to the React client and ready for UI use; per-endpoint enforcement is an unscoped future project. `entities/user_project/api/router.py` calls `publish_profile_changed(user_id)` on every mutation.
- **Admin credentials endpoints (2026-04-29)**: `GET /api/v1/admin/auth/by-user/{user_public_id}` (Modules.USERS, can_read) returns `{username, has_auth}` (never the hash); `POST /api/v1/admin/auth/set-credentials/{user_public_id}` (Modules.USERS, can_update) creates-or-updates the Auth row and links to the User in one call. Backed by `dbo.ReadAuthByUserId` sproc + `AuthService.set_credentials_for_user`. **Does NOT revoke existing refresh tokens** on password change — security follow-up tracked in TODO.md.
