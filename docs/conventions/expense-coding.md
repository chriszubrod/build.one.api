- **Expense coding cockpit (U-005, 2026-07-14) — the ONLY sanctioned app→QBO expense write.** Card spend lands in QBO as Purchases auto-coded to the placeholder GL account `Cost of construction : NEED TO CATEGORIZE` (58999). `entities/coding_suggestion/` is the coding **queue + trust-gate + metric store** (`dbo.CodingSuggestion` — ⚠️ was `entities/expense_coding_item/` / `dbo.ExpenseCodingItem` until U-652 migrated both; that entity dir now holds only `__init__.py`, one row per target 58999 line, **seeded lazily on queue read** — the queue itself (`ReadExpenseCodingQueue`, `purchase/sql/qbo.expense_coding_queue.sql`) reads `qbo.PurchaseLine` staging directly, so a 58999 line is queue-visible the moment the purchase tick stages it; `ReadExpenseCodingQueue` surfaces the Ramp `PrivateNote` + `Credit` + `SyncToken`; router gated `Modules.EXPENSES`: queue/metrics/claim/flag/**confirm**/suggest). A **deterministic** suggestion engine (`business/suggestion_service.py` behind the pure `hint_extractor.py` seam — abbrev-exact + `FindProjectForInvoice` + `FindSubCostCodeForReply` + a NEW vendor→dominant-SubCostCode history) fills `{Project, SubCostCode, Description}` + reason + confidence, or flags "needs cardholder follow-up"; a `SubCostCode` with no `ItemSubCostCode` mapping is dropped (never suggest an unwritable coding). On human confirm, a **purpose-built single-line SURGICAL recode** — `PurchaseExpenseConnector.recode_purchase_line` — round-trips the **RAW** QBO Purchase JSON (`get_purchase_raw` → mutate ONLY the target line dict → `update_purchase_raw`) so every sibling line + its QBO line Id + all header fields stay byte-identical and the amount is untouched. **Do NOT reuse the dormant `sync_to_qbo_purchase`** (it rebuilds all lines from local data and silently drops any lacking a SubCostCode→Item mapping → sibling loss — verified P0). **Fail-closed on SyncToken**: the outbox handler `_handle_recode_purchase_line` catches `PurchaseChangedInQboError`/`QboSyncTokenMismatchError` → marks the item `changed_in_qbo` (re-review), it must NEVER reach the worker's generic refresh-and-retry (which would clobber a concurrent QBO/Ramp edit and doesn't support this entity_type). The recode write is **double-gated**: it enqueues only when BOTH `ALLOW_QBO_WRITES` AND `ALLOW_EXPENSE_RECODE_WRITES` (default off) are true — both checked **at the top of `confirm()`** (U-058a, supersedes the U-005 Phase-F record-on-gate-off criterion): with either gate off, confirm **rejects HTTP 422** (plain-string `detail` = `"qbo_writes_disabled"` / `"recode_writes_disabled"`) with **zero DB writes** — never a recorded-but-unenqueued `'confirmed'` (the 2026-07-16 trap: 44 codings looked confirmed but never reached QBO; recovered by manual outbox backfill). Contract for the web cockpit: `GET /expense-coding/metrics` exposes `recode_writes_enabled` (the AND of both gates); a confirm `200` always carries `enqueued: true`. ⛔ **Gate-P2 precondition before real-volume writes:** one controlled live recode + re-pull + a live fail-closed test (no sandbox realm wired as of build).
