- **Review-submit notifications (May 2026, forward-of-original; Expense added later — see end of bullet)**: First-time draft Bill creation auto-fires an email notification via `entities/review/business/notification_service.py`. The notification is a **draft FORWARD of the original vendor email** (`Bill.SourceEmailMessageId → EmailMessage.GraphMessageId → me/messages/{id}/createForward`) so reviewer replies stay in the same MS Graph conversation thread as the source. Recipients resolved by `dbo.ResolveReviewRecipientsByBillId` walking Bill → BillLineItem → Project → UserProject (filtered to `Role.Name='Project Manager'` / `'Owner'`) → User → Contact. **TO** = all PMs, **CC** = all Owners, **BCC** = `Settings.invoice_inbox_email` (always). Submitter excluded. Subject is auto-prefixed by Graph (`FW: <original>`). HTML preamble is prepended to the forwarded body via 2-step POST createForward + PATCH (PATCH is content-type-aware: `\n` → `<br>` for plain-text source emails; `<body>`-tag injection for HTML source emails). Preamble opens with a slash-joined firstname greeting (`Cassidy/Zach,`) when PMs are resolved. PDF attachment inherited from the source. Channel: MS outbox `Kind='send_mail'` → `create_forward_draft` (mode=draft, default) or `forward_message` (mode=send) by `REVIEW_NOTIFICATION_MODE` env var. Failure-isolated — never rolls back Bill or Review row. **Bills without `SourceEmailMessageId`** (manual web-UI creation) are silently skipped today; synth-email fallback design captured in TODO.md. v1 limits: see `project_review_notifications.md` memory + TODO.md "Review-submit notifications follow-ups". Runbook: `docs/runbooks/review-notification-failed.md`. **Reviewer assignment requires populating `UserProject.RoleId`**; no React UI yet, do via SQL. **Expense** has its own path (`ReviewNotificationService.enqueue_for_expense`, fired from `ReviewService.create` on the initial submit only): recipients via `ResolveReviewRecipientsByExpenseId`, an HTML-composed `send_mail` (no source email to forward) with the receipt attached by `blob_url` reference (never downloaded on the request path), then an auto-advance to `in_review` and `ExpenseService.enqueue_coding_recode_on_submit` (U-486 C2) — all DB-only; ~20–30 sequential connections, no inline external HTTP.
